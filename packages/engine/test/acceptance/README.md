# Acceptance tests

This directory belongs to the Verifier. The Builder may read it and may not change it (build spec §4).

- `manifest.json` lists, by base name, the test files each slice must pass. The end-to-end journey, row M01, is listed under slice 5 (`M01-kernel-journey.test.mjs`, first in that slice's list): it needs nothing later, and it is the slice-5 build's central target. Slice 7 is the same journey read through the public API (`M01-journey-through-the-api.test.mjs`).
- Test files are named `M<nn>-<slug>.test.mjs`; the slug is lower-case letters, digits and hyphens. A row may have several files. Each named case in a row is its own subtest with its own fixture.
- `COVERAGE.md` lists every named case of every row in `docs/acceptance/sdlc-M1-acceptance-plan-Astra.md`: its file, the slice it is listed under, and whether it is written. It is how one Verifier session hands over to the next.
- `contract/` holds the Verifier's expected transition tables. Cases are generated from these, never from the engine's own tables.
- `harness/` holds the test side of the seam and `SEAM.md`, which states exactly what the engine must provide (build spec §8).

The tests of slices 1 to 7 exist (`harness/journey.mjs` makes the journey for both of row M01's files); slice 3's were written by two Verifier sessions in sequence (`COVERAGE.md` says which cases each wrote). Later slices add theirs. From slice 4 the procedure is lighter (errata E31): the fewest cases that pin each row's required result, and no stand-in engine or self-check. Through slice 3 a self-check and a stand-in ("witness") engine lived in `harness/selfcheck/`; E31 froze them, they were deleted after slice 6 was verified, and they are in git history (`harness/SEAM.md` §21). Nothing is to be run in their place.

From slice 2 on the tests drive the engine through a scripted backend. `harness/scripted/child.mjs` is the role program the engine launches in place of a coding agent (it can also leave a descendant process behind, close its own output while it goes on, and end its output without a line ending, which the cases written after the slice-2 reviews use); `harness/scripted.mjs` scripts it and instructs the scripted execution boundary; `harness/runs.mjs` holds the fixtures, commands and waits; `harness/invariants.mjs` holds what the store must show about a run; `harness/transitions.mjs` reads the contract tables and generates the transition cases; `harness/endings.mjs` brings a run to each of the ways it can end, with or without a fault on one store transaction, and reduces a project's store to facts that two executions can be compared by (the run-end fault matrix, `contract/run-end-faults.json`). For the git rows of slice 3: `harness/repos.mjs` makes the fixture repositories and reads what a repository and a checkout hold (and makes a repository hostile, unreadable or slow); `harness/journal.mjs` reads journaled operations, revisions, the ref registry and out-of-band observations and holds the two judgements most cases end in, "this run's snapshot was committed, exactly" and "nothing of this run was accepted"; `harness/gitruns.mjs` holds the fixtures and scripts those cases share.

Run with `node scripts/run-tests.mjs acceptance --slice N` for slices 1 to N, or without `--slice` for the full suite. The runner builds first and runs one file at a time. It fails on a failing, skipped or todo test, a file with no passing test, a file not named for a known row, a file not listed in the manifest, a listed file that is missing, and, on a full run, any row without a file.

For slice 4: `harness/ledger.mjs` reads the ledger and sends corrections; `harness/records.mjs` reads records and their chunk receipts and holds the judgement "store and records directory agree"; `harness/backup.mjs` runs the `surety store` commands. Row M67 cuts power with an unprivileged shim: `harness/powerloss/shim.c` is compiled with `cc` at test time and loaded with `LD_PRELOAD` into the engine, and `harness/powerloss.mjs` cuts power by killing every process under it and putting each file back to what was last synced. `M67-power-loss-shim-is-faithful.test.mjs` needs no engine: it shows on plain SQLite and plain git that the shim tells synced from unsynced. `harness/SEAM.md` §60 says what the shim models and what it does not.

For slice 5: `harness/gates.mjs` holds the fixtures (a plan with requirements, checks, check executions, test targets, classifications, a validation-scope approval, reuse entries, the Alpha exception's evidence), the gate and authorization commands, the store reads, the test's own computation of the protected fingerprint, and the helpers that make a candidate and run a scripted Verifier or Reviewer on it; `harness/decisions.mjs` reads decisions, approvals and effect intents, holds the judgements the decision rows end in (a preview is complete for its kind; an answer with an old preview is refused with no effect; the next generation shows what changed; an effect held between its consumption and its execution is invalidated), and installs the scripted notification sink, `harness/scripted/notify.mjs`, a program the engine runs in place of a notification transport. `contract/decisions.json` says what each enabled decision kind's preview must bind. Check executions, classifications, baseline approvals and reuse entries are fixtures and are labelled as test setup: M1 has no check runner and no classifier, and no test qualifies one. `harness/SEAM.md` §§65 to 85 state the contract.

For slice 6: `harness/mono.mjs` holds waits and durations on the monotonic clock, which every slice-6 file uses for what it times. `harness/boundary.mjs` writes requests byte for byte and holds the judgements "every response carries the defensive headers" and "nothing is granted to another origin". Row M68 drives real Chromium and Firefox with Playwright (`harness/browser.mjs`); the page they load is the harness's own shell, `harness/shell/`, which the engine serves from a directory the test gives it. `harness/sse.mjs` is a client of the two event streams that can stop reading without closing; `harness/stream-clients.mjs` runs twenty such clients in a process of their own for the load case. `harness/load.mjs` builds the one-gibibyte store of row M71 in one transaction, reads a process's peak resident memory, and judges a latency: every sample is paired with a control request, a sample whose control was slow is void, and too few valid samples is a failure. `harness/reads.mjs` reads the projections; `harness/filesystem.mjs` names the kind of filesystem a path is on; `harness/launch-lint.mjs` inspects the engine's source for a process started outside the choke point. `contract/load-limits.json` holds the qualified load limits and `contract/filesystems.json` the kinds of filesystem an engine home may not be on. `harness/SEAM.md` §§87 to 97 state the contract.

Row M71's first file needs about 2 GiB of free space under the temporary directory while it runs, and removes it afterwards. On a host whose temporary directory is memory-backed, run the tests with `TMPDIR` set to a directory on a disk filesystem: from slice 6 the engine refuses a home on a memory-backed filesystem.
