# Verifier contract tables

Expected values the acceptance tests compare the engine against. They are derived from the sources (build spec §2) with the corrections in build spec §6, and from names the Verifier fixed where the sources were silent (recorded in `../harness/SEAM.md`). A test never reads the engine's own tables to learn what is legal or what a default is (build spec §4, Plan §2).

| File | Holds | Sources | First used by |
|---|---|---|---|
| `work-items.json` | The work-item transition table: each kind's path, the common templates limited to the statuses a kind reaches, Stop and Abandon from every run-owning status, the stored-continuation rule, the role of each M1 kind (`assessment`: the Architect, E24 item 5, since slice 3). Read through `../harness/transitions.mjs`. | D1 A.5, §4.3; build spec §6 #11; Review B10; F §4.1 | M09, M13, M14 (slice 2) |
| `run-lifecycle.json` | The run, execution-domain and lease tables; the reason classes and workspace disposition of each run outcome; what each outcome does to its work item in slice 2; what the expiry of a run lease leaves (`lease_expiry`). | D1 A.5, §§4.1, 4.5, 8.1, 8.3, 16; E7; E27 item 3; build spec §6 #1, #2, #12, #13; Review B08, B17 | M09–M18 (slice 2) |
| `run-end-faults.json` | The run-end fault matrix: the ten ways a run can end in slice 2 and the five endings that pass through a commit or an integration (slice 3, second session), the store transactions on each ending's path (each named by an event it writes), what each ending leaves, and how long a faulted ending is given. Read through `../harness/endings.mjs`. | E28 item 1; D1 §§3.5, 3.6, 4.1, 4.3, 4.5, 10, 12.1; E27 items 3 and 5 | M15 (slice 3, both sessions) |
| `config.json` | The closed configuration: every engine and ungoverned project key, its default, range and unit; the effective decision-target defaults of the eleven M1 decision kinds. | D1 A.9, A.8; build spec §6 #20; Review B17; E18; RN R2, R4 | M07 (slice 1) |
| `snapshot-validation.json` | What snapshot validation accepts and rejects: the paths a Builder and an Architect may change, with examples of each; the cases of what lies outside the diff (row M19) and of what a snapshot may not hold (row M20); the one rule that gives a violation its reason class; file names that must stay data. Read through `../harness/journal.mjs` (`VALIDATION`). | F §4.1; E2; D1 §§5.1, 5.2, 7.3, 7.8, 17(3), 17(6); RN R2; build spec §6 #15; Review B05 | M09, M19, M20 (slice 3) |
| `journal.json` | The git journal: the four journal kinds with their operation kinds; the five boundaries at which a barrier can stop the engine and what is durable at each; an operation's ordinary course; the journal's transition table with correction 14; the five probe outcomes for each kind, with the fixture that produces each and the way on it must lead to; the attempt statuses, the admission rule and the derivation of an operation's status with correction 16; the receipts each finalizer writes. Read through `../harness/journal.mjs` (`JOURNAL`, `PROBE`, `ATTEMPTS`) and `../harness/probes.mjs`, which generates the probe and crash cases. | D1 §§2.5, 3.5, 4.4, 4.5, 6.3, 7.3, 7.5, 7.7 to 7.10, 16, A.3, A.5; Plan §2; build spec §6 #14, #16, §8; Review B05, B17 | M07, M19–M25 (slice 3, first session); M04, M26–M34 (second session) |
| `decisions.json` | The eleven decision kinds M1 enables: what each is about, the options it can offer, the dependencies its preview must bind (the manifest keys), whether consuming it records an effect intent; the answer codes. Read through `../harness/decisions.mjs` (`DECISIONS`, `CODES`). | D1 A.8, §§9.7, 10; build spec §3 and §6 #5, #22; RN R4; Review B12, B18; E25 item 4 | M45–M58 (slice 5) |

The remaining transition tables (decision, intent, finding, proposal, assessment, authorization) are added by the slice that first generates cases from them. They must apply build spec §6 correction 4 to D1 A.5; corrections 14 and 16 are applied in `journal.json`. Slice 5 generated no cases from a transition table (E31: no generated matrix), so it added none: the transitions its cases rely on are stated in `../harness/SEAM.md` (§75 for an authorization, with correction 4; §§69, 74 and 76 for a proposal, a finding, an assessment, a decision and an intent).
