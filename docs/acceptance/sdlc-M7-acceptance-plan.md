## 1. What M7 adds

An execution mode `rapid_prototype` on a project (always T1; its bootstrap policy preset committed as revision 1: `autonomy: phase`, `phase_size {1,2}`, `design: off`, `alpha_deploy: on_phase_complete`, `budget_run_billable_tokens` per S5); five editable iteration limits (`prototype_budget_tokens` 1,500,000, `prototype_budget_usd_estimated` 15, `prototype_runtime_seconds` 2700, `prototype_repairs_per_stage` 2, `prototype_repairs_per_iteration` 4); durable iterations (`prototype_iterations`, `runs.iteration`); the preparation approval (`prototype_preparation_approval`) and the one-shot `brief_preparation` run writing the minimal spec and the `prototype_brief` record; the brief on `spec_approval`; the first plan published `policy_authorized` within bounds (R1, S4); dispatch accounting against the iteration allowance with the effective per-run allowance (S5); the runtime deadline; Stop, Resume, Discard and Iterate; the iteration reads and the JSON receipt; Alpha current vs historical consistent across modes (S3).

**What M7 does not cover:** promotion ("Develop this further"), Edit brief, a scoped reusable preparation allowance, remote Alpha targets, observed subagents inside one invocation, any real-provider run.

## 2. Fixtures

The scripted backend's per-kind scripts: `brief_preparation` writes `.surety/spec/spec.md` (3–5 objectives, each a requirement) and reports the brief; the prototype `replan` writes the architecture, modules, roadmap and the iteration's single phase plan (≤2 stages, or 3 for the out-of-bounds case); `stage_build`, `check_authoring`, `verification` as M5's scripts. Deployment through the scripted adapter and the qualification fixture (kernel) or the real `local_service` unit (sandbox). Usage reported by the script per invocation (complete, cached, absent, or cut by a cancellation/restart).
