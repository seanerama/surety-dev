### 2.4 How results are observed

From outside the engine, as in M4: the API (`GET …/sessions/:r`, `GET …/spec`, `GET …/plan`, `GET …/pace`, the project read, decisions, events, work items, runs and their ledger rows), the store (D6 A.3's tables and columns), git (the integration branch, `refs/surety/spec-change/<seq>`, the checkpoint commits), the filesystem (workspaces, the engine home, the run directory), the scripted backend's captured packages and call counts, and on the host, read only, section 2.3's reads. A scripted role's report of what it was given is read from the captured package, which the harness writes, never from the role's reply. Deterministic barriers, the controlled clock and crash-and-reopen as M1 to M4.

### 2.5 Honest `not_exercised`

Only M438's exhaust file off the designated host, and the real rows if Sean does not run them. A sandbox or project row on a host without a running user manager fails. A project-lane journey whose envelope admits one domain at a time passes on the serial path and records it in its pace read; the pipelined path is M437's and M438's to pin, not the journey's. A project-lane journey that reaches its end only because a fixture installed an intermediate state is not a pass (section 1).

### 2.6 Details D6 leaves to the tests, which the Verifier fixes in the seam

The scripted backend's turn script format and how a test reads a captured package; the transcript record's `text_ref` form and how a test reads it; the engine's entry text for a parse finding (its fields, not its prose); the `spec_semantics` row's shape and the `semantic_digest`'s inputs; the `plan_check` record's `subjects` and `changes_*` forms per reason; the bundle record's shape; the `spec_impact` record's shape and its dependency manifest; the `check_obligations` row and how a resolution is recorded; the completion binding's and the deployment request key's fields; the conformance source projection's exact exclusions; the form of `adopted_tests` and its `dependency_boundary` on a proposal; how a test drives a save racing a turn and a settlement barrier; how a test scripts `MemAvailable` and `memory.current` and observes `resource_envelope` holds; the pace read's JSON shape, its `unknown` marker and the `host_observations` it reads; how a test drives an engine restart between observations; the hands-on script's steps; the real lane's step names and confirmation phrase (BS5 §12); the adopted fixture's claims and which is false; the reason codes' exact names where D6 A.4 and A.6 propose them (E20: the Verifier pins them).
