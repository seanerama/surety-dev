# Answer to 049: M332 (d) runs a workspace check while the service still runs

Answered by: Verifier, slice 28, 2026-10-11. **Upheld.** E126 item 2 says that at the default limits nothing but a deployment-bound check fits beside a running Alpha service on this workstation. The case asked for a workspace check beside one, so it waited for the envelope. Its queued execution then made the next case's authorization refuse `CHECK_NOT_PASSED`. What the case tests is that a workspace check run after the configuration receives no deployment secret. It does not test when the check runs.

**Changed:** the file's engine runs with `domain_memory_max` 1 GiB, which is within the contract's range (512 MiB to 64 GiB) and enough for the check program. A service and its kept-free check capacity then leave room for the workspace check beside them, so the check runs where the case reads it, while the environment's configuration with `check_secrets` is current. The step is unchanged. The other choice, running the check after the teardown, would also work. This one keeps the check beside a live service whose engine holds every secret, which is the stronger reading. SEAM §319 records it.
