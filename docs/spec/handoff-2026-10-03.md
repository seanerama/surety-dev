## 3. How the build was driven (keep doing this)

- **Roles never share a session.** Verifier writes `packages/engine/test/acceptance/`, `docs/acceptance/objections/`, `docs/acceptance/reports/`. Builder writes `packages/engine/src/`, `migrations/`, `api/`, `test/unit/`, objections. Reviewer writes nothing. The driver (you) writes owner paths only: `docs/` outside those, `scripts/`, package files, `CLAUDE.md`. **The driver never edits acceptance tests or engine source**, not even to resolve a conflict in logic; a mechanical merge resolution in a Verifier document (keep both paragraphs) was the one exception taken, and it was said so.
- **Agents:** the Agent tool, `subagent_type: general-purpose`, background. Builder and Reviewer with `model: "opus"`; Verifier at the session default. Each in its own git worktree under `.claude/worktrees/` (hidden by `.git/info/exclude`), branch `verify/<name>` or `build/<name>` from `main`, `npm ci` there first. Brief each as a peer: goal, what is already known and ruled out, the files to read, the rules, the exact report wanted. Tell a Builder it will be **messaged** (SendMessage) when the Verifier's tests reach `main`, so both can start at once; when the Verifier reports, run the boundary check, merge, then message the Builder.
- **The driver reruns before merging.** `node scripts/run-tests.mjs acceptance --slice N` (or `--slice 7` for the whole suite, about 20 minutes), `npm run test:unit`, `node scripts/check-role-boundary.mjs <role> main <branch>`. Run the long ones in the background with output to a file; the foreground limit is 600 s. Merge with `--no-ff`, a message that records the figures, and the trailers (`Surety-Role: owner`, `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`).
- **Lean procedure (E31, E40):** one Reviewer pass per slice; a finding confirmed serious gets one Verifier test and one Builder fix, judged by the tests, no second review; everything else is recorded for later. Fewest test cases. No stand-in engine. **Scope is frozen:** a new finding is either needed by the journey or a recorded deferral; every addition, even a small read, is flagged to Sean as an addition.
- **Reviews must reproduce.** Tell a Reviewer that anything it calls serious must be confirmed by running the engine, with the command and output; unconfirmed suspicions in a separate list. The three slice reviews found 12 real defects this way (E37, E41, E42), including secret leakage, lost accounting, a gate passing on an unreadable repository and engines killing each other's git processes.
- **Record every decision as an errata entry** (`E<n>`, provisional when the driver decided under delegation, decided when Sean did), update `E1 to E<n>` in `docs/README.md` and the build spec's section 2, and keep `docs/README.md` indexing new documents.

## 4. Host and tooling facts that cost time when unknown

- **Clock:** this WSL2 host's wall clock steps back about 1.8 s every 30 s and jumps forward about 15 minutes when Windows wakes from sleep. The harness and engine durations are on the monotonic clock; a sleep during a run can still fail cases legitimately because leases are on the wall clock by decision.
- **Two engines on one machine disturbed each other until E41 item 1** (an engine killed other engines' git processes). Fixed; but still never run two acceptance files in parallel in one working copy, and tell parallel agents that a "could not be snapshotted" or `repo_unreadable` failure must be rerun alone before it is believed.
