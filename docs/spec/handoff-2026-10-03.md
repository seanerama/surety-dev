## 3. How the build is driven (keep doing this)

- **Roles never share a session.** Verifier writes `packages/engine/test/acceptance/`, `docs/acceptance/objections/`, `docs/acceptance/reports/`. Builder writes `packages/engine/src/`, `migrations/`, `api/`, `test/unit/`, objections. Reviewer writes nothing. The driver writes owner paths only (`docs/` outside those, `scripts/`, package files, `CLAUDE.md`) and never edits acceptance tests or engine source. A document the Verifier drafts for an owner path (the M2 plan) goes under `docs/acceptance/reports/` and the driver adopts it with a `git mv` in an owner commit.
- **Agents:** the Agent tool, `subagent_type: general-purpose`, background. Builder, Reviewer and architect agents with `model: "opus"`; Verifier agents at the session default (Fable 5.1; Sean asked and was told; he did not ask for a change). Each in its own worktree under `.claude/worktrees/`, branch `verify/m2-s<N>`, `build/m2-s<N>`, `design/<doc>-draft<n>`, cut from `main`, `npm ci` there first. Brief each as a peer with the goal, the files to read in order, the rules, and the exact report wanted; tell a Builder it will be messaged when the cases land. Resume a finished agent with SendMessage (its context intact) for a fix round or an objection answer; a resumed Verifier needs a new worktree since the old one is removed after merge.
- **Per slice (E31, E40):** Verifier and Builder start together; the Verifier's cases merge after the boundary check; the Builder is messaged; one Reviewer pass on the build branch (anything serious must be reproduced by running the engine, with the command and output); each confirmed serious finding gets one Verifier case and one Builder fix, judged by the tests, no second review; the driver reruns `--slice <N>` and `npm run test:unit` on the fixed branch in the background (foreground limit 600 s; the suite takes about 20 minutes) and the builder boundary check from a clean scratch worktree, then merges `--no-ff` with the figures in the message and the trailers `Surety-Role: owner` and `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; a closing Verifier pass records `npm test` (or `--slice`) on `main` and updates the not-claimed list; every decision becomes an errata entry (`E<n>`, provisional when the driver decided under delegation, decided when Sean did), `docs/README.md` and the build specs' "E1 to E<n>" updated, new documents indexed.
- **Objections:** a Builder files `docs/acceptance/objections/NNN-<row>-<slug>.md` on its branch; the driver copies it to a scratch path and resumes the Verifier in a new worktree on `verify/m2-s<N>-obj` to answer in `NNN-….answer.md`; merge the answer; message the Builder. ## 4. Host and tooling facts that cost time when unknown

- **Clock:** the WSL2 wall clock steps back about 1.8 s every 30 s and jumps forward about 15 minutes when Windows wakes. Harness durations are on the monotonic clock. A single timing failure in a full run while another agent loads the machine is rerun alone before it is believed (it has happened once per full run under load; alone the file passes).
- **Never run two acceptance files in parallel in one working copy.** Engines of different homes no longer disturb each other (E41 item 1), so agents in separate worktrees may run single files while the driver's full run goes.
- **Versions qualified for M1:** Ubuntu 24.04 on WSL2 kernel 6.6.87.2, Node v22.22.0, SQLite 3.53.4 via better-sqlite3 13.0.3, git 2.43.0, Playwright 1.58.2 (Chromium 145.0.7632.6, Firefox 146.0.1). **Host facts for D2** (not a qualification): cgroup v2 with `nsdelegate`, the user's systemd running with `cpuset cpu io memory pids` delegated, unprivileged user namespaces, Docker 29.2.1 reachable (not used), util-linux 2.39.3, `slirp4netns` present, `newuidmap` absent, no sudo, unprivileged BPF disabled, Claude Code 2.1.288 and Codex 0.159.2 at `~/.local/bin`.
