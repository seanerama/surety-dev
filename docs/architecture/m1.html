The work describes the task. A run is one attempt with its own invocation, workspace, authority and outcome. Resume creates a new run.

A commit is not acceptance.

Integration records source. A nominated candidate binds an immutable revision. Its checks, findings and sign-offs determine gate satisfaction.

Inside M1

Durable orchestration

  • One local engine; one active run per project.
  • Transactional transitions, scheduler, fenced leases and cancellation.
  • Engine-created workspaces, snapshots, commits, integration and journal recovery.
  • Protected-change proposals and authorized protected versions.
  • Stage and Alpha-authorization gates; findings and sign-offs.
  • Eleven decision kinds with preview validation and scoped effects.
  • Usage ledger, budgets, redacted records, retention, backup and restore.
  • Local API and bounded event streams; a minimal browser test harness.

Still disabled or unqualified

  • Real Claude / Codex backends and model spend.
  • Qualified containment and control-plane isolation: D2.
  • The real protected check runner and semantic diff classifier: D3.
  • Provider sessions and continuation: M2.
  • Deployment, publication and Alpha completion.

Limits that matter when reading this diagram

Scripted does not mean isolated.

M1 role processes are not qualified as unable to access the engine’s control plane. The diagram shows responsibility, not a security sandbox. A real backend remains refused pending D2.

Power-loss evidence is bounded.

The selected shim discards unsynced file contents. It does not model lost directory entries or prove that the host honours sync. Backup and recovery claims must state this limit.

These are qualification targets.

Sean’s M1 load envelope is 5 projects, 20 clients and a 1 GB database, with a 250 ms API latency bound. This page does not claim that qualification has passed.

Known limits in the source also include no Git LFS, no custom merge drivers or partial clones; a concurrent repository-config rewrite race remains assigned to D2. E38 records automatic fix-work creation as an open decision before M2. This guide does not silently fill that gap.
